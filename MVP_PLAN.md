## БЛОК 1: Авторизация и управление контентом

### Как это должно работать

**Ты (Эдуард — admin):**
- Входишь через `/admin` → вся панель управления
- Добавляешь/редактируешь аудиозаписи (загрузка + метаданные)
- Пишешь теоретические статьи в WYSIWYG-редакторе
- Управляешь деревом обучения (разделы, темы)
- Видишь дашборд с аналитикой

**Студент:**
- Регистрируется сам (email + пароль) или анонимно
- После входа видит персональный прогресс
- Сессии и результаты тестов записываются в Supabase автоматически
- НЕ видит admin/дашборд в навигации

### Что нужно сделать

#### 1.1 Поменять пароль admin
```sql
-- В Supabase Dashboard → SQL Editor:
-- Сменить пароль через Supabase Auth → Users → admin@admin.com → Reset password
```

#### 1.2 Убрать пароль admin из кода
Сейчас `VITE_ADMIN_PASSWORD` захардкожен в коде AdminLogin.jsx как запасной вариант.
**Нужно:** убрать этот fallback, оставить только Supabase Auth.

#### 1.3 Правила RLS (Row Level Security) — ужесточить
```sql
-- Только admin может писать в audio_records:
CREATE POLICY "admin_write_audio" ON audio_records
FOR ALL USING (
  EXISTS (SELECT 1 FROM user_profiles WHERE id = auth.uid() AND role = 'admin')
);

-- Студенты читают только свои test_attempts:
CREATE POLICY "user_own_attempts" ON test_attempts
FOR SELECT USING (user_id = auth.uid());
```

#### 1.4 Загрузка аудиофайлов (приоритет!)
Сейчас аудио лежит на GitHub (raw.githubusercontent.com). Это ненадёжно и медленно.
**Лучше:** Supabase Storage (бесплатно до 1 GB).

**Шаги:**
1. Supabase Dashboard → Storage → создать bucket `audio-files` (public)
2. В AdminPanel уже есть форма загрузки — проверить что она пишет в Storage
3. В `audio_records.audio_url` хранить Supabase Storage URL

## БЛОК 2: ИИ-чат (тьютор-клиницист)

### Текущее состояние
- Edge Function `ai-chat` работает через OpenRouter
- Модель: `openai/gpt-4o-mini` — норм, но можно дешевле
- Системный промпт уже ограничивает тематику — **хороший**

### Что поменять: модель

**Рекомендация:** `deepseek/deepseek-chat` (DeepSeek V3)
- Цена: ~$0.07/1M токенов (в 8× дешевле gpt-4o-mini)
- Качество: отличный русский язык, сильная медицинская база
- Не "несёт шлак" при правильном промпте

**Альтернатива:** `google/gemini-flash-2.0` — тоже дёшево, быстрее отвечает

#### Изменение в Edge Function (одна строка):
```typescript
// Было:
model: "openai/gpt-4o-mini",

// Станет:
model: "deepseek/deepseek-chat",
```

#### Улучшенный системный промпт:
```
Ты — ИИ-тьютор по клинической аускультации для студентов-медиков.

РОЛЬ: обучающий клиницист, строгий но поддерживающий.

РАЗРЕШЕНО отвечать:
- Характеристики сердечных шумов (систолические, диастолические, их тоны)
- Клапанные пороки и их аускультативная картина
- Лёгочные феномены (хрипы, крепитация, плевральный шум)
- Точки аускультации, методика выслушивания
- Патофизиология, связанная с акустическими феноменами
- Дифференциальная диагностика по аускультативным данным

ЗАПРЕЩЕНО:
- Ответы на вопросы вне медицинской аускультации
- Конкретные назначения лечения для реального пациента
- Общая медицина, хирургия, фармакология (не по теме тренажёра)

При вопросе не по теме: вежливо верни студента к аускультации.
Ответ: 2-3 абзаца максимум. Язык: русский.
Стиль: клинический, точный, с примерами из практики.
```

### Дополнительные улучшения чата

| Улучшение | Сложность | Ценность |
|---|---|---|
| Стриминг ответов (текст появляется постепенно) | Средняя | Высокая — UX |
| Кнопки быстрых вопросов ("Что такое стеноз МК?") | Низкая | Средняя |
| Сохранение истории чата в Supabase | Средняя | Средняя |
| Связь чата с текущим прослушиваемым звуком | Высокая | Очень высокая |

**Самое ценное:** кнопка "Спросить про этот звук" прямо на карточке аудио — чат открывается с контекстом нужного шума.

### Приоритет: ⭐⭐ Важно, но не блокирует

## БЛОК 3: Режим тестирования

### Текущее состояние (хорошее!)
- 3 режима: сердечные / лёгочные / все
- 3 сложности: лёгкий / средний / сложный
- Сохраняет результаты в `test_attempts`
- На medium/hard — ИИ генерирует теоретические вопросы и клинические кейсы

### Проблемы
1. **Нет "разбора ошибок" после теста** — студент видит только счёт, не знает что не так
2. **Нет спейсед-репетиции** — слабые звуки повторяются не чаще
3. **ИИ-генерация на medium/hard может падать** — generate-quiz Edge Function нестабильна
4. **Нет режима "свободной практики"** — только формальный тест с таймером

### Что нужно добавить

#### 3.1 Экран разбора результатов (приоритет!)
После теста показывать каждый вопрос с:
- ✅ Правильный ответ
- ❌ Твой ответ (если ошибся)
- 📖 Краткое объяснение почему

**Реализация:** в `test_attempts.details` уже есть `{ audioName, isCorrect, userAnswer, correctAnswer }` — нужно только показать это в UI.

#### 3.2 Режим "Слушай и учись" (без оценки)
Свободный просмотр: листаешь карточки звуков, слушаешь, видишь подсказку "нажми когда угадаешь". Без давления оценки, но с запоминанием правильных/неправильных.

#### 3.3 Адаптивный выбор вопросов
Брать звуки, по которым у студента низкая точность (из `test_attempts.details`), чаще чем те, что он хорошо знает.

**Реализация:** в `testGenerator.js` добавить весовую функцию, читающую историю ошибок студента.

#### 3.4 Стабилизация medium/hard
`generate-quiz` Edge Function сейчас может падать тихо (возвращает plain вопросы). Надо:
- Добавить retry логику
- Или встроить генерацию клинических кейсов прямо в `ai-chat` Function

### Приоритет по фичам тестирования:

| Фича | Приоритет | Трудозатраты |
|---|---|---|
| Экран разбора ошибок | ⭐⭐⭐ | 1-2 часа |
| Адаптивный выбор | ⭐⭐ | 2-3 часа |
| Режим "свободной практики" | ⭐⭐ | 3-4 часа |
| Спейсед-репетиция (SRS) | ⭐ | 5+ часов |

## Технические заметки

**Где хранятся данные:**
- Контент (аудио, теория, структура) → Supabase (облако), не на Beget
- Статические файлы (HTML/JS/CSS) → Beget сервер
- Аутентификация → Supabase Auth

**Где менять ИИ-модель:**
- Файл: `supabase/functions/ai-chat/index.ts`
- После изменения: `supabase functions deploy ai-chat`
- Или: через Supabase Dashboard → Edge Functions → редактировать код

**Ключ для ИИ:**
- Текущий ключ в Edge Function — OpenRouter
- Новый ключ sk-P8...Le25 — нужно уточнить провайдера (если OpenRouter, формат должен быть `sk-or-v1-...`)
- Если другой провайдер (OpenAI-compatible) — поменять `OPENROUTER_API_URL` на нужный endpoint
